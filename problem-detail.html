Problem statement

A calculator has mixed up its display. Whenever you enter a number, it must rearrange the digits so that every position contains a different digit from the original number.

For each integer x in the inclusive range [l, r], find the smallest number that can be formed this way. Use every digit exactly once, and do not allow a leading zero. If no rearrangement is possible, print -1.

Equal digits are indistinguishable: moving a digit to a position that originally contained the same value does not satisfy the rule.

Input

The input contains two integers l and r.

  • 10 ≤ l ≤ r ≤ 109
  • 0 ≤ r − l ≤ 100

Output

Print r − l + 1 lines. For each number in the range, in increasing order, print its smallest valid rearrangement, or -1 if none exists.

Examples

Input
21 24
Output
12
-1
32
42
Input
100 102
Output
-1
-1
210

Explanation

For 21, swapping the digits gives 12. For 22, both positions would still contain 2, so no answer exists. For 102, the smallest valid number without a leading zero is 210.

Editorial

Try solving the problem before opening the hints below.

Hint 1 · Build the answer from left to right

Try the remaining digits in increasing order. A digit cannot equal the original digit at the current position, and the first digit cannot be zero. Keep the first choice that allows a complete valid answer.

Hint 2 · Remember impossible states

Represent the used digit positions with a bitmask. The number of set bits gives the next output position. Cache whether each mask can be completed, so repeated branches do not need to be explored again.

Solution approach and complexity

Sort the original digit positions by their digit values. At each state, try every unused position whose digit differs from the original digit at the next output position. Skip a leading zero. The state is feasible if any allowed choice reaches a feasible next state; the full mask is the base case.

If the empty mask is infeasible, print -1. Otherwise, reconstruct the answer by taking the smallest allowed digit that leads to a feasible state. This produces the lexicographically smallest answer, which is also the smallest number because all candidates have the same length.

For d digits, the time complexity per number is O(d · 2d) after sorting, and the extra space is O(2d). Here d ≤ 10.
